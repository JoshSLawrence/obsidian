DNS requests to Azure Public DNS will resolve to a Private IP:

- Only for requests that originate from Azure Cloud

- A Private DNS Zone matching the request is linked to
    the VNet of the endpoint making the request

- A record exists in the Private DNS Zone for the given request ^BhdarubI



1. The Client will make a network request to Azure SQL in the Spoke Vnet

2. DNS would need to be resolved

3. The On Prem DNS VM forwards the request to a specific Azure VM

4. The Azure VM forwards the request to Azure Public DNS

5. Because the Azure VM is the one making the DNS request to
    Azure Public DNS, a Private DNS Zone for SQL is linked, and a
    record exists for the requested Azure SQL instance in the Zone...
    ...Azure Public DNS will return the Private IP to the Azure VM

6. The Azure VM returns the same Private IP to On Prem DNS

7. On Prem DNS returns the same Private IP to the client that
    made the original DNS request

8. With the Private IP address in-hand, our On Prem network routes send
    the client's request across the VPN Tunnel to the Hub Vnet

9. Thanks to the Peering between the Hub and Spoke Vnets, a system route
    already exists which will take the request that landed in the Hub Vnet and
    send it over to the Spoke Vnet

10. Now that the request has finally made it to the Spoke Vnet (the home of
    the Azure SQL instance that is the target of the request) the request is
    sent directly to the SQL instance ^SFZSKssN
