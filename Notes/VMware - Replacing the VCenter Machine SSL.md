# Overview

VCenter uses a self-signed certificate for SSL encryption. Generally, servers and workstations within the domain will not trust this SSL certificate. Traffic will still be encrypted but the site will issue a warning and show up as "untrusted."

This can be remedied by installing the VMware Certificate Authority (VMCA) root certificate to the workstation or server connecting to VCenter. Alternatively a certificate issued by a trusted Certificate Authority (CA) can installed to the VCenter appliance. 

This second case is what will be in scope for this document, additionally this document assumes the CA is the root authority and no intermediate will be in play.

## Generate a CSR

A Certificate Signing Request (CSR) is required by the Certificate Authority (CA) before an certificate can be issued.

While there are a multitude of ways to generate a CSR, for this request the vSphere Certificate Manager command-line utility will be used. This utility can be found running on the VCenter appliance.
### Step 1 - Access the Certificate Manager Utility

SSH to the VCenter appliance, and enter the shell with the following command:

```bash
shell
```

Optionally, create a directory to store any certificate files and enter into that directory:

```bash
mkdir /cert
cd /cert
```

Finally, run the Certificate Manager executable by passing the full path to the executable in the shell:

```bash
/usr/lib/vmware-vmca/bin/certificate-manager
```

At this stage, the command line interface graphic for the Certificate Manager utility is visible.

![[vmware-certmanager-p1.png]]
### Step 2 - Activate the CSR and Key Operation

With the utility running you must select your utility operation, authenticate, and declare the directory for output.

Finally, you must specify if you wish to use the existing CSR configuration or start over. If you are opting to start over, see [Step 3 Option 1](#Option%201) for a quick way to complete a new form outside of the Certificate Manager utility and then come back to this step.

| Prompt (In Order)                                        | Description                                                                                                                                                                                                    |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Option**                                               | Enter `1` into the shell to activate the operation: `Replace Machine SSL certificate with Custom Certificate`.                                                                                                 |
| **Enter username**                                       | The default value should be `Administrator@vsphere.local`, simply enter to continue with this user. Alternatively, pass in a username for an account in VCenter with sufficient privileges for this operation. |
| **Enter Password**                                       | Enter the password for the account passed in the previous step.                                                                                                                                                |
| **Option**                                               | Enter `1` into the shell to activate the operation `Generate Certificate Signing Request(s) and Key(s) for Machine SSL certificate`.                                                                           |
| **Output directory path**                                | Enter the target output directory such as `/cert` created in Step 1. The CSR and private key generated by the utility will output to this directory.                                                           |
| **certool.cfg file exists, Do you wish to reconfigure?** | This field will only show up if a CSR was requested previously. You can reuse the previous form to generate a new CSR instantly or start from scratch with `Y`/`N`.                                            |

### Step 3 - Complete the CSR Form
#### Option 1

If you would like to generate a new CSR from scratch, you can modify the existing form by accessing the `certool.cfg` file directly using your text editor of choice. 

The path to this file can be found in the example command below:

```bash
vi /usr/lib/vmware-vmca/share/config/certool.cfg
```

Once `certool.cfg` has been updated, access the Certificate Manager utility again and pass in `Y` when the prompt: `certool.cfg file exists, Do you wish to reconfigure?` appears. Your new CSR will generate instantly and the following 2 files will be output to the directory declared in the previous step: `vmca_issued_csr.csr` and `vmca_issued_key.key`
#### Option 2

Alternatively, you can fill out a new form within the Certificate Manager utility if you responded `N` to the prompt: `certool.cfg file exists, Do you wish to reconfigure?`

| Prompt (In Order)                         | Description                                                                                                                |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Enter proper value for 'Country'**      | Residing country of the entity requesting the CSR.                                                                         |
| **Enter proper value for 'Name'**         | Can be anything, just make it appropriate, optionally for internal services just use the server FQDN or App Name.          |
| **Enter proper value for 'Organization'** | Organization Name, such as "Company Inc," of the entity requesting the CSR.                                                |
| **Enter proper value for 'OrgUnit'**      | **Optional** - sub division/department within the Organization of the entity requesting the CSR.                           |
| **Enter proper value for 'State'**        | Assuming United States - the residing state of the entity requesting the CSR.                                              |
| **Enter proper value for 'Locality'**     | Assuming United States - the residing community of the entity requesting the CSR.                                          |
| **Enter proper value for 'IPAddress'**    | **[Optional, Comma Delimited]** - IP Addresses of the endpoints the certificate will be installed to.                      |
| **Enter proper value for 'Email'**        | Contact email of the entity requesting the CSR.                                                                            |
| **Enter proper value for 'Hostname'**     | **[Comma Delimited]** FQDN(s) for the host(s) the certificate will be installed to. e.g. `subdomain.domain.topleveldomain` |
| **Enter proper value for VMCA 'Name'**    | FQDN for the VCenter Certificate Authority. This should be the appliance running VCenter.                                  |

After the last prompt is answered 2 files will be output to the directory declared in previous steps: `vmca_issued_csr.csr` and `vmca_issued_key.key`
## Acquire the New Certificate

Now that a CSR has been created, it can be provided to a Certificate Authority which will then generate and sign a new certificate. The next series of steps will assume the Certificate Authority is Active Directory Certificate Services.
### Step 1 - Submit the CSR

In a browser, navigate the the following address: `https://<FQDN of the CA>/certsrv`. You may be prompted to sign in with a domain account authorized for CA operations.

On the landing page, select `Request a certificate`. (See below)

![[active-directory-certificate-services-p1.png]]

On the following screen select, `advanced certificate request.` (See below)

![[active-directory-certificate-services-p2.png]]

The large text box labeled: `Base-64-encoded certificate request (CMC or PKCS #10 or PKCS #7)

Paste-in the text within the `vmca_issued_csr.csr` file generated in previous steps and select an appropriate template.

You can copy the text by opening the file on the appliance with a text editor, or by copying the file to your local machine from the appliance using SFTP, and then open the file and copy the text.

Finally, submit the request:

![[active-directory-certificate-services-p3.png]]

The next page will indicate your certificate is issued, be sure to download the base64 encoded version. You can export the certificate directly from the CA mmc.exe if you navigate away from this page.

![[active-directory-certificate-services-p4.png]]

### Step 2 - Copy the Certificate to the VCenter Appliance

Congratulations, you now have a fresh certificate. The final step before it can be installed is simply copying the cert to the VCenter appliance... with that said, there is a catch.

This step will use [WinSCP](https://winscp.net/eng/index.php) to copy the newly issued certificate to the VCenter appliance.

Once WinSCP is installed fill in the required fields for a new SFTP connection, but before clicking `login`, click the `Advanced...` button. (See below)

![[winscp-vcenter-p1.png]]

With the Advanced window now open, click `SFTP`, and in the `SFTP server:` box fill in the following:

```
shell /usr/libexec/sftp-server
```

![[winscp-vcenter-p2.png]]

Click `OK`, now you are set to click `login` and click through any prompts that appear.

Your SFTP session to the VCenter appliance should now be established. Simply copy over the newly issued cert to the desired directory. (Such as `/cert` created in an earlier step)

You will also need to copy over the root certificate for the Certificate Authority. A new copy of this certificate can be exported from the mmc.exe plugin for Active Directory Certificate Services if required.
## Import the Certificate
### IMPORTANT

- Once the new cert is successfully imported and installed, VCenter services will restart. This process can last ~15 minutes. During this time the VCenter web interface will be down. 
- ESXi hosts will continue to run VMs during the VCenter downtime, so the runtime and availability of your VMs should be unaffected.
### Step 1 - Access the Certificate Manager Utility (Again)

SSH to the VCenter appliance, and enter the shell with the following command:

```bash
shell
```

Run the Certificate Manager executable by passing the full path to the executable in the shell:

```bash
/usr/lib/vmware-vmca/bin/certificate-manager
```

Finally, select the correct operation and pass values for the subsequent prompts:

| **Prompt (In Order)**                                                     | Description                                                                                                                                                                                                            |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Option**                                                                | Enter `1` into the shell to activate the operation: `Replace Machine SSL certificate with Custom Certificate`.                                                                                                         |
| **Enter username**                                                        | The default value should be `Administrator@vsphere.local`, simply enter to continue with this user. Alternatively, pass in a username for an account in VCenter with sufficient privileges for this operation.         |
| **Enter Password**                                                        | Enter the password for the account passed in the previous step.<br>- **Option** - Enter `1` into the shell to activate the operation `Generate Certificate Signing Request(s) and Key(s) for Machine SSL certificate`. |
| **Option**                                                                | Enter `2` into the shell to activate the operation `Import custom certificate(s) and key(s) to replace existing Machine SSL certificate`.                                                                              |
| **Please provide valid custom certificate for Machine SSL**               | Enter the full path to the newly issued cert copied to the VCenter appliance. e.g. `/cert/newcert.cer`                                                                                                                 |
| **Please provide valid custom key for Machine SSL**                       | Enter the full path to the key issued when the CSR was generated in an earlier step. e.g. `/cert/vmca_issued_key.key`                                                                                                  |
| **Please provide the signing certificate of the Machine SSL certificate** | Enter the full path to the root certificate of the Certificate Authority. e.g. `/cert/rootcert.cer`                                                                                                                    |
| **You are going to replace Machine SSL cert using custom cert**           | This is the ***final*** check before import/install is executed. Simply pass in `Y` or `N`                                                                                                                             |

In the active SSH session, the shell will output the status of the certificate import/install. The following message will be displayed upon a complete and successful operation:

```
Status : 100% Completed [All tasks completed successfully]
```
### Step 2 - Certificate Installation Validation

This is the final step of the entire process, and thankfully it is quick.

1. Simply navigate to the VCenter web interface in your browser of choice. (aka the web portal)
2. Inspect site certificate and confirm it matches the configuration for the newly issued certificate from your Certificate Authority.

You are done!
